## Memory

Auto memory is only for how I want you to work, and only what has no better home:

- **Cross-project preferences go into your rules** (a rule module, or your profile's `CLAUDE.md`).
  Propose the rule change instead of saving a memory.
- **Project knowledge goes into the project.** A decision, a domain term, a gotcha or an infra
  quirk is written into that repo's docs (the doc for its area, else `docs/decisions.md`) and
  committed with the work, so the team and a new machine have it too.
- **Never save progress.** Plans, in-flight work, "waiting for X" and what shipped live in the
  plan file, the PR and git. A memory about a finished feature gets deleted.
- **Memory keeps the rest:** personal feedback about one project that can't go in its repo
  (private, or the repo is public), and pointers to systems outside the repo.
