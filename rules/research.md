## Research and external information

- **Prefer your own cached knowledge first.** For stable facts — language semantics, standard
  APIs, established patterns — answer from what you already know. Reach for web search only
  when the information is likely newer than your knowledge or inherently volatile: versions,
  releases, prices, statuses, news.
- **Never trust the web without confirmation.** A single search result is a claim, not a fact.
  Cross-check anything non-trivial against a primary source or a second independent one before
  acting on it, and say explicitly when something remains unverified.
- **Tool and library documentation goes through the context7 MCP server first.** It serves
  current docs for frameworks, SDKs, and CLIs — use it before web search, even for libraries
  you think you know. Fall back to the web only when context7 has nothing on the topic.
- **Learn from the best.** When surveying how other projects do something, read long-established,
  widely used tools (thousands of stars, years of releases), not small or new repos, and not only
  projects from our own niche. Name the reference set in any research brief, and say which
  projects were read.
